# Contributing

Thanks for considering a contribution to this project.

## Ways to contribute

- **Bug reports**: open an issue using the "Bug report" template. Include relevant logs, environment variables (never paste secrets), and steps to reproduce.
- **Feature requests**: open an issue using the "Feature request" template.
- **Documentation**: the docs live in `docs/` and are built with [MkDocs Material](https://squidfunk.github.io/mkdocs-material/). Typo fixes and clarifications are always welcome.
- **Code**: see the workflow below.

## Development setup

```bash
git clone https://github.com/tommasomarchionni/omp-usage.git
cd omp-usage
npm install
cp .env.example .env
# edit .env with your configuration
```

Build and test locally:

```bash
npm run build
npm run test
npm run lint
npm run typecheck
```

## Running the test suite locally

The full suite runs in Node.js (no Docker required):

```bash
npm run test
```

This runs:

1. **ESLint** on all packages — static analysis for common mistakes.
2. **TypeScript typecheck** — catches type errors.
3. **Vitest unit tests** — exercises core logic.
4. **Integration tests** (`npm run test:integration`) — real exporter processes, signals, SQLite, plugin → exporter end to end.
5. **Package smoke test** — the packed tarballs installed in a clean project on Linux and macOS.
6. **Format check** — `npm run format:check`.

## Pull request checklist

- [ ] `npm run check` passes locally (format, lint, typecheck, unit and integration tests).
- [ ] New environment variables are documented in `.env.example` and `docs/configuration.md`.
- [ ] Behavioral changes are reflected in the relevant `docs/*.md` page.
- [ ] The PR title is a Conventional Commit (`fix(exporter): ...`, `feat!: ...`). `CHANGELOG.md` is generated by release-please from it; do not edit it by hand.

## Commit style

Pull requests are squash-merged, and the **PR title** becomes the commit that release-please reads. It must follow [Conventional Commits](https://www.conventionalcommits.org/), and CI enforces this. Use a scope when the change targets one package: `plugin`, `exporter`, `protocol`, `docs`, `ci`, `deps`. A `!` or a `BREAKING CHANGE:` footer triggers a major release (minor while below 1.0).

A pre-commit hook (husky + lint-staged) formats and lints the staged files. It is installed by `npm install`.
